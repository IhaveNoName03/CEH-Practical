CEH v12 - Module 10

Denial-of-Service

Denial-of-Service (DoS) and Distributed Denial-of-Service (DDoS) attacks have become a major threat to computer networks. These attacks attempt to make a machine or network resource unavailable to its authorized users. Usually, DoS and DDoS attacks exploit vulnerabilities in the implementation of the TCP/IP model protocol or bugs in a specific operating system. In a DoS attack, attackers flood a victim's system with non-legitimate service requests or traffic to overload its resources, bringing the system down and leading to the unavailability of the victim's website, or at least significantly slowing the victim's system or network performance. The goal of a DoS attack is not to gain unauthorized access to a system or corrupt data, but to keep legitimate users from using the system. Perpetrators of DoS attacks typically target sites or services hosted on high-profile web servers such as banks, credit card payment gateways, and even root nameservers. In general, DoS attacks target network bandwidth or connectivity: bandwidth attacks overflow the network with a high volume of traffic using existing network resources, thus depriving legitimate users of these resources; connectivity attacks overflow a computer with a flood of connection requests, consuming all available OS resources, so that the computer cannot process legitimate users' requests. As an expert ethical hacker or penetration tester, you must possess sound knowledge of DoS and DDoS attacks to detect and neutralize attack handlers and mitigate such attacks. The labs in this module give hands-on experience in auditing a network against DoS and DDoS attacks.

Scenario: DoS and DDoS attacks have become popular because of the easy accessibility of exploit plans and the negligible amount of brainwork required while executing them. These attacks can be very dangerous because they can quickly consume the largest hosts on the Internet, rendering them useless. The impact includes loss of goodwill, disabled networks, financial loss, and disabled organizations. In a DDoS attack, many applications pound the target browser or network with fake exterior requests that make the system, network, browser, or site slow, useless, disabled, or unavailable. The attacker initiates the DDoS attack by sending a command to zombie agents. These zombie agents send a connection request to a large number of reflector systems with the spoofed IP address of the victim. The reflector systems see these requests as coming from the victim's machine instead of from the zombie agents because of the spoofing of the source IP address. Hence, they send the requested information (response to connection request) to the victim. The victim's machine is flooded with unsolicited responses from several reflector computers at once, which may reduce performance or may even cause the victim's machine to shut down completely. As an expert ethical hacker or pen tester, you must have the required knowledge to perform DoS and DDoS attacks to be able to test systems in the target network. In this lab you will gain hands-on experience in auditing network resources against DoS and DDoS attacks.

Objective: Perform a DoS attack by continuously sending a large number of SYN packets; perform a DoS attack (SYN flooding, Ping of Death (PoD), and UDP application layer flood) on a target host; perform a DDoS attack; detect and analyze DoS attack traffic; detect and protect against a DDoS attack.

Overview of Denial of Service: A DoS attack is a type of security break that does not generally result in the theft of information. However, these attacks can harm the target in terms of time and resources. Further, failure to protect against such attacks might mean the loss of a service such as email. In a worst-case scenario, a DoS attack can mean the accidental destruction of the files and programs of millions of people who happen to be surfing the Web at the time of the attack. Some examples of types of DoS attacks: flooding the victim's system with more traffic than it can handle; flooding a service (such as an internet relay chat (IRC)) with more events than it can handle; crashing a TCP/IP stack by sending corrupt packets; crashing a service by interacting with it in an unexpected way; hanging a system by causing it to go into an infinite loop.

Overview of DoS and DDoS Attacks: DDoS attacks mainly aim at the network bandwidth; they exhaust network, application, or service resources, and thereby restrict legitimate users from accessing their system or network resources. In general, the following are categories of DoS/DDoS attack vectors:

  • Volumetric Attacks: consume the bandwidth of the target network or service. Techniques: UDP flood attack, ICMP flood attack, Ping of Death and smurf attack, pulse wave and zero-day attack.
  • Protocol Attacks: consume resources like connection state tables present in network infrastructure components such as load-balancers, firewalls, and application servers. Techniques: SYN flood attack, fragmentation attack, spoofed session flood attack, ACK flood attack.
  • Application Layer Attacks: consume application resources or services, thereby making them unavailable to other legitimate users. Techniques: HTTP GET/POST attack, Slowloris attack, UDP application layer flood attack, DDoS extortion attack.

Overview of DoS and DDoS Attack Detection: Detection techniques are based on identifying and discriminating the illegitimate traffic increase and flash events from the legitimate packet traffic. The following are the three types of detection techniques: Activity Profiling (profiles based on the average packet rate for a network flow, which consists of consecutive packets with similar packet header information); Sequential Change-point Detection (filters network traffic by IP addresses, targeted port numbers, and communication protocols used, and stores the traffic flow data in a graph that shows the traffic flow rate over time); Wavelet-based Signal Analysis (analyzes network traffic in terms of spectral components).

Key Concepts

  • DoS vs. DDoS: A Denial-of-Service (DoS) attack originates from a single source to make a resource unavailable; a Distributed Denial-of-Service (DDoS) attack coordinates many compromised machines (zombies/bots) via handlers/agents to flood the target, often using spoofed source IPs and reflector systems. DDoS attacks mainly aim at network bandwidth and exhaust network, application, or service resources.
  • SYN Flood: Exploits the TCP three-way handshake by sending a flood of SYN packets without completing the handshake. The victim keeps partially open (half-open) connections in its listening/backlog queue, exhausting connection state tables and preventing legitimate connections. Tool: Metasploit auxiliary/dos/tcp/synflood (RHOST, RPORT, SHOST) or hping3 (-S --flood).
  • UDP Flood: Connectionless flood of UDP packets (often to random or application ports such as NetBIOS 139). The target spends resources processing/checking ports and replying with ICMP "port unreachable", consuming bandwidth and CPU. Easily spoofed. Tool: hping3 -2 -p <port> --flood; LOIC (UDP method).
  • ICMP Flood: Flood of ICMP echo request (ping) packets overwhelming bandwidth/processing. Includes Smurf (amplification) and Ping of Death.
  • HTTP Flood: Layer 7 attack sending HTTP GET/POST requests mimicking legitimate users; can be high-rate (HOIC) or slow (Slowloris holding connections open). Harder to distinguish from legitimate traffic. Tool: HOIC (HTTP flood with boosters), LOIC (HTTP).
  • Smurf Attack: ICMP amplification: attacker sends ICMP echo requests to a broadcast address with the victim's spoofed source IP; all hosts on the broadcast network reply to the victim, flooding it.
  • Fraggle Attack: UDP-based amplification similar to Smurf: attacker sends UDP echo requests to a broadcast address with the victim's spoofed source IP; broadcast hosts reply to the victim.
  • Ping of Death (PoD): Sends malformed/oversized ICMP packets (e.g., 65,538 bytes) exceeding the 65,535-byte maximum of RFC 791 IP. The target's packet reassembly process may crash, freeze, or destabilize the system. Tool: hping3 -d 65538 -S -p 21 --flood.
  • Teardrop Attack: Sends fragmented packets with overlapping fragment offsets; the target's IP reassembly logic crashes or hangs when trying to reassemble them. A fragmentation attack.
  • Other Protocol/Application Attacks: ACK flood, fragmentation attack, spoofed session flood, Slowloris, UDP application layer flood, pulse wave, zero-day, DDoS extortion.

Tools

hping3 Metasploit HOIC LOIC Raven-Storm Anti DDoS Guardian

  • hping3: Packet crafting/scanning tool supporting TCP/UDP/ICMP/raw-IP. Used for SYN flood (-S --flood), PoD (-d 65538 ... --flood), and UDP application flood (-2 -p <port> --flood). Supports IP spoofing (-a) and high volume (--flood).
  • Metasploit: Penetration testing framework; uses auxiliary/dos/tcp/synflood (set RHOST, RPORT, SHOST) to perform SYN flooding while spoofing the source IP.
  • HOIC (High Orbit Ion Cannon): HTTP flood tool attacking up to 256 URLs simultaneously; high-speed multi-threaded HTTP flood with "boosters" (e.g., GenericBoost.hoic) to bypass countermeasures; configurable threads and power.
  • LOIC (Low Orbit Ion Cannon): Network stress/DoS tool targeting web applications; floods with TCP/UDP/HTTP requests; configurable method, threads, and power bar.
  • Raven-Storm: Python 3 DDoS tool supporting Layer 3, 4, and 7 attacks; interactive (rst) with l4 module, ip/port/threads/run commands.
  • Anti DDoS Guardian: Host-based real-time protection; monitors incoming/outgoing flows, limits connection/bandwidth rates, and allows Block IP of offending sources via Traffic Detail Viewer.

Mitigation

  • Rate Limiting: Cap the number of requests/connections per source to absorb floods.
  • SYN Cookies: Avoid allocating state for half-open connections; encode connection state in the SYN-ACK so only completed handshakes consume resources.
  • Firewalls / IPS / IDS: Filter malicious traffic, block attack signatures, and limit connection rates.
  • Load Balancers / Traffic Scrubbing: Distribute and clean traffic; blackhole or scrub attack traffic upstream.
  • Host-based Protection: Anti DDoS Guardian monitors flows and blocks offending IPs (Block IP).
  • Detection Techniques: Activity profiling, sequential change-point detection, and wavelet-based signal analysis to distinguish attack traffic.
  • Cloud/DDoS Services: DOSarrest, DDoS-GUARD, Cloudflare, and similar scrubbing/CDN services for organization-wide protection.

Exam Tips

  • DoS = single source; DDoS = many sources (zombies/bots) coordinated by handlers.
  • SYN flood exploits the TCP three-way handshake and fills the half-open connection queue; mitigated by SYN cookies.
  • Smurf = ICMP amplification via broadcast; Fraggle = UDP amplification via broadcast.
  • Ping of Death = oversized ICMP packet (>65,535 bytes) crashing reassembly; Teardrop = overlapping fragments crashing reassembly.
  • HTTP flood is Layer 7 and mimics legitimate traffic; Slowloris holds connections open.
  • UDP is connectionless and easily spoofed; UDP floods often target application ports.
  • hping3 flags: -S (SYN), -2 (UDP), -d (data size), -a (spoof IP), -p (port), --flood.
  • Metasploit module: auxiliary/dos/tcp/synflood with RHOST/RPORT/SHOST.
  • Anti DDoS Guardian: real-time monitor/limiter; Block IP turns the session red.
  • Mitigations to remember: rate limiting, SYN cookies, firewalls, IPS/IDS, scrubbing, cloud protection.
  • Detection: activity profiling, sequential change-point detection, wavelet-based signal analysis.
  • Always obtain proper authorization before performing DoS/DDoS tests.

The intruder sends unlimited SYN packets (requests) to the host system faster than the system can handle them. Normally the connection establishes with the TCP three-way handshake, and the host keeps track of the partially open connections while waiting in a listening queue for response ACK packets. Metasploit is a penetration testing platform that allows a user to find, exploit, and validate vulnerabilities; it provides the infrastructure, content, and tools to conduct penetration tests and comprehensive security auditing. The Metasploit framework has numerous auxiliary module scripts that can be used to perform DoS attacks. Lab 2 - Detect and Protect Against DoS and DDoS Attacks: Task 1: Detect and Protect Against DDoS Attacks using Anti DDoS Guardian

Anti DDoS Guardian / LOIC / Wireshark

What/when: Anti DDoS Guardian is a DDoS attack protection tool that protects IIS servers, Apache servers, game servers, Camfrog servers, mail servers, FTP servers, VOIP PBX, SIP servers, and other systems. It monitors each incoming and outgoing packet in real time and displays local address, remote address, and other information of each network flow. It limits network flow number, client bandwidth, client concurrent TCP connection number, and TCP connection rate, and also limits UDP bandwidth, UDP connection rate, and UDP packet rate. Here Windows Server 2019 and 2022 attack Windows 11 (10.10.1.11) with LOIC while Anti DDoS Guardian on Windows 11 detects the flood and blocks attacker IPs (10.10.1.19, 10.10.1.22) via Block IP in the Traffic Detail Viewer.
