Overview of Hacking Mobile Platforms and Android

Smartphones are widely used for business/personal purposes and are a treasure trove for attackers. Threats grow with Internet connectivity, apps, and communication methods. Mobile devices are susceptible to desktop/laptop/web/network threats too. Connectivity via 3G/4G/5G, Bluetooth, Wi-Fi, or wired connections creates attack points along the data path. Android is a Google software environment (OS, middleware, key apps) based on Linux, designed for smartphones/tablets. Its stack: System Apps, Java API Framework, Native C/C++ Libraries, Android Runtime/ART, HAL, Linux kernel (six sections, five layers). Android's openness and large user base make it a prime target. Attacks include DoS, Man-in-the-Disk, and Spear phone attacks. BYOD policies increase exposure. iOS is Apple's mobile OS; jailbreaking is the iOS equivalent of rooting.

Key Concepts
  • Mobile platform: OS/environment for smartphones/tablets (Android, iOS); stores sensitive data and supports commerce.
  • Android: Google's Linux-based mobile OS with a layered stack (System Apps, Java API Framework, Native libs, Android Runtime/ART, HAL, Linux kernel).
  • iOS: Apple's mobile OS; jailbreaking bypasses restrictions to gain root access.
  • APK (Android Package Kit): Application package file format for Android apps; malformed APKs/URLs are used to entice victims.
  • ADB (Android Debug Bridge): Command-line tool to communicate with a device; USB or wireless via daemon on TCP port 5555.
  • Backdoor APK: Malicious payload (e.g., android/meterpreter/reverse_tcp) that grants remote control (Meterpreter shell).
  • msfvenom: Metasploit payload generator; creates binary payloads/APKs for Android.
  • Metasploit Framework: Ruby-based modular pen-testing platform; multi/handler receives reverse shells; Meterpreter interactive shell.
  • Meterpreter: Metasploit payload providing an interactive shell to explore/execute code on target.
  • Reverse TCP: Payload that connects back to attacker's LHOST/LPORT (default 4444).
  • SET (Social-Engineer Toolkit): Python-driven social engineering toolkit; credential harvester clones sites.
  • Credential Harvester: SET attack that clones a website and captures submitted usernames/passwords in plain text.
  • LOIC (Low Orbit Ion Cannon): Open-source network stress/DoS tool flooding target with TCP/UDP packets.
  • PhoneSploit: Tool to exploit ADB-enabled Android devices: shell access, screenshots, app list/launch, MAC/Inet, netstat, file download.
  • AndroRAT: Remote administration tool for Android; persistent backdoor starting on boot; collects location, SIM, IP, MAC; interpreter shell.
  • Mobile malware: Trojans, ransomware, adware, spyware targeting mobile devices.
  • Mobile security: Patching, app vetting, permissions, antivirus, MDM, avoiding unknown sources.
  • MDM (Mobile Device Management): Centralized management/enforcement of security policies on mobile devices.
  • Rooting: Gaining privileged (root) access on Android.
  • Jailbreaking: Bypassing iOS restrictions to gain root access.
  • BYOD (Bring Your Own Device): Employees using personal devices for work; increases attack surface.
  • Man-in-the-Disk: Android attack exploiting insecure external storage to tamper with app data.
  • Spear phone attack: Targeted mobile attack.
  • Online APK analyzers: Sixo (sisik.eu), SandDroid, Apktool (javadecompilers.com) for decompiling/inspecting APKs.
  • AndroidManifest.xml: Declares package name, version, components, requested permissions; serialized binary XML inside APK.
  • Requested permissions: App capabilities requested at install/runtime; key indicator of malicious behavior.
  • Malwarebytes Security: Antimalware for Android: blocks/detects/removes adware/malware, privacy audits, safer browsing.
  • Other Android hacking tools: NetCut, drozer, zANTI, Network Spoofer, DroidSheep.
  • Other Android vuln scanners: X-Ray 2.0, Vulners Scanner, Shellshock Scanner (Zimperium), Yaazhini, QARK.
  • Other mobile AV/anti-spyware: AntiSpy Mobile, Spyware Detector, iAmNotified, Privacy Scanner.

Lab 2: Secure Android Devices using Various Android Security Tools - Overview

Lab Scenario, Objectives, and Overview

Lab Scenario: Like personal computers, mobile devices store sensitive data and are susceptible to various threats. Therefore, they should be properly secured in order to prevent the compromise or loss of confidential data, lessen the risk of various threats such as viruses and Trojans, and mitigate other forms of abuse. Strict measures and security tools are vital to strengthening the security of these devices. Android's growing popularity has led to increased security threats, ranging from typical malware to advanced phishing and identity theft techniques. As a professional ethical hacker or penetration tester, you should scan for any unsecured settings on the mobile device you are assessing, and then take appropriate action to secure them. You must do this before hackers exploit these vulnerabilities by; for example, downloading sensitive data, committing a crime using your Android device as a launchpad, and ultimately endangering your business.

Lab Objectives: Analyze a malicious app using online Android analyzers; secure Android devices from malicious apps using Malwarebytes Security.

Overview of Android Security Tools: Android security tools reveal the security posture of particular Android platforms and devices. You can use them to find various ways to strengthen the security and robustness of your organization's mobile platforms. These tools automate the process of accurate Android platform security assessment.
