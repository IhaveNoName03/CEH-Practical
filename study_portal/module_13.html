Hacking Web Servers

Most organizations consider their web presence to be an extension of themselves. Organizations create their web presence on the World Wide Web using websites associated with their business. Most online services are implemented as web applications. Online banking, search engines, email applications, and social networks are just a few examples of such web services. Web content is generated in real-time by a software application running on the server-side. Web servers are a critical component of web infrastructure. A single vulnerability in a web server's configuration may lead to a security breach on websites. This makes web server security critical to the normal functioning of an organization.

Scenario: Hackers attack web servers to steal credentials, passwords, and business information. They do this using DoS, DDoS, DNS server hijacking, DNS amplification, directory traversal, Man-in-the-Middle (MITM), sniffing, phishing, website defacement, web server misconfiguration, HTTP response splitting, web cache poisoning, SSH brute force, web server password cracking, and other methods. Attackers can exploit a poorly configured web server with known vulnerabilities to compromise the security of the web application. A leaky server can harm an organization. In the area of web security, despite strong encryption on the browser-server channel, web users still have no assurance about what happens at the other end. Systems are constantly being attacked, so IT security professionals need to be aware of the common attacks on web server applications.

Objective: Perform web server hacking and other tasks that include, but are not limited to: footprint a web server using various information-gathering tools and inbuilt commands; enumerate web server information; crack remote passwords.

Overview of Web Server: Most people think a web server is just hardware, but a web server also includes software applications. In general, a client initiates the communication process through HTTP requests. When a client wants to access any resource such as web pages, photos, or videos, then the client's browser generates an HTTP request to the web server. Depending on the request, the web server collects the requested information or content from data storage or the application servers and responds to the client's request with an appropriate HTTP response. If a web server cannot find the requested information, then it generates an error message. A penetration (pen) tester or ethical hacker for an organization must provide security to the company's web server, including performing checks on the web server for vulnerabilities, misconfigurations, unpatched security flaws, and improper authentication with external systems.

Exam Essentials: Hacking Web Servers

Scenario & Objective

Scenario: An ethical hacker or penetration tester must provide security to the company's web server. This includes performing checks on the web server for vulnerabilities, misconfigurations, unpatched security flaws, and improper authentication with external systems. Web server fingerprinting is an essential task before proceeding to hack or exploit a webserver, because most attacks and exploits are specific to the type and version of the server being used by the target.

Objective: Footprint a web server using various information-gathering tools and inbuilt commands; enumerate web server information; crack remote passwords. Gather valuable system-level data such as account details, OS, software versions, server names, and database schema details.

Overview of Web Server Footprinting

By performing web server footprinting, it is possible to gather valuable system-level data such as account details, OS, software versions, server names, and database schema details. Use Telnet utility to footprint a web server and gather information such as server name, server type, OSes, and applications running. Use footprinting tools such as Netcraft and httprecon to perform web server footprinting. Web server fingerprinting tools can extract information from the target server. Web server fingerprinting is an essential task for any penetration tester. Before proceeding to hack or exploit a webserver, the penetration tester must know the type and version of the webserver as most of the attacks and exploits are specific to the type and version of the server being used by the target.

Key Concepts
  • Web Server: Includes both hardware and software. A client initiates communication through HTTP requests; the server collects requested content from data storage or application servers and responds with an HTTP response; generates an error message if the requested information cannot be found.
  • Web Server Footprinting: Collecting as much information as possible about the target web server and analyzing it to find lapses in current security mechanisms. Reveals remote access capabilities, ports and services, OS, software versions, server names, account details, and database schema details. May involve Internet/newsgroup/bulletin board searches, Whois, and tools (Netcraft, httprecon).
  • Banner Grabbing: Probing HTTP servers to determine the Server field in the HTTP response header. Performed with Netcat, Telnet, and HTTP methods (e.g., GET / HTTP/1.0). Gathers content type, last modified date, accept ranges, ETag, and server information.
  • HTTP Methods: GET (retrieve resource), POST (submit data), HEAD (headers only), PUT (upload/replace resource), DELETE (remove resource), TRACE (echo request; can expose vulnerabilities such as Cross-Site Tracing), OPTIONS (lists allowed methods), CONNECT (tunneling), PATCH (partial update). OPTIONS reveals allowed methods; TRACE may be abused; PUT/DELETE can alter server content if misconfigured.
  • Web Server Attacks: DoS/DDoS, DNS server hijacking, DNS amplification, directory traversal, MITM, sniffing, phishing, website defacement, web server misconfiguration, HTTP response splitting, web cache poisoning, SSH brute force, web server password cracking, FTP credential cracking (dictionary attack), and brute-force attacks.
  • Web Server Fingerprinting Tools: Ghost Eye (Python 3 info-gathering: Whois, DNS, EtherApe, Nmap port scan, HTTP header grabber, Clickjacking test, Robots.txt scanner, Link grabber, IP location, traceroute); Skipfish (active web app reconnaissance, recursive crawl + dictionary probes, interactive sitemap, security checks); httprecon (advanced fingerprinting: banner grabbing, status code enumeration, header ordering analysis); Netcat and Telnet (banner grabbing); Nmap + NSE (http-enum, hostmap-bfk, http-trace, http-waf-detect); Uniscan (ping, traceroute, nslookup, static/dynamic/stress checks, Bing/Google searches); THC-Hydra (network login cracker for FTP and other protocols).

Exam Tips
  • Footprinting is the first step of hacking web servers; gather type and version of the web server before exploitation.
  • Banner grabbing reveals the Server field and other HTTP response headers; use Netcat/Telnet with GET / HTTP/1.0 followed by two Enter presses.
  • Ghost Eye menu choices: 3 Whois Lookup, 2 DNS Lookup, 6 Clickjacking Test (on certifiedhacker.com).
  • Skipfish command: skipfish -o /home/attacker/test -S /usr/share/skipfish/dictionaries/complete.wl http://[IP]:8080; let run ~5 minutes, then Ctrl+C; report in /home/attacker/test/index.html.
  • httprecon: enter target URL and port 80, click Analyze; observe Get existing (server, e.g., nginx) and GET long request / Fingerprint Details tabs.
  • Nmap NSE web enumeration: nmap -sV --script=http-enum, nmap --script hostmap-bfk, nmap --script http-trace -d, nmap -p80 --script http-waf-detect.
  • Uniscan options: -q directory scan, -we file check (robots.txt, sitemap.xml), -d dynamic test; report at /usr/share/uniscan/report/<IP>.html.
  • FTP credential cracking: first verify port 21 with nmap -p 21, then hydra -L Usernames.txt -P Passwords.txt ftp://<IP>; cracked example Martin / apple.
  • Hydra syntax: -L username list, -P password list, target ftp://IP.
  • Always obtain proper authorization; use these techniques only in authorized labs/environments.

Key procedural steps / narrative: Click Parrot Security to switch to the Parrot Security machine. (Use sample password file Passwords.txt containing a list of passwords.) Assume you are an attacker and have observed that FTP service is running on the Windows 11 machine. Perform an Nmap scan on the target machine (Windows 11) to check if the FTP port is open: click the MATE Terminal icon, type sudo su and press Enter, type toor in the [sudo] password for attacker field and press Enter (password not visible). Type nmap -p 21 [IP Address of Windows 11] and press Enter (IP here 10.10.1.11). Observe that port 21 is open. Check if an FTP server is hosted: type ftp [IP Address of Windows 11] and press Enter; you will be prompted to enter user credentials (implies FTP server hosted). Try entering random usernames and passwords in an attempt to gain FTP access (password not visible); you will not be able to log in. Close the terminal window. Now perform a dictionary attack using THC Hydra. Click Places from the top section and click Desktop from the drop-down options. Navigate to the CEHv12 Module 13 Hacking Web Servers folder and copy the Wordlists folder (Ctrl+C). Paste the copied folder (Wordlists) on the Desktop (Ctrl+V); close the window. Click the MATE Terminal icon to open a Terminal window; type sudo su and press Enter; type toor in the [sudo] password for attacker field and press Enter (password not visible). Type hydra -L /home/attacker/Desktop/Wordlists/Usernames.txt -P /home/attacker/Desktop/Wordlists/Passwords.txt ftp://[IP Address of Windows 11] and press Enter (IP here 10.10.1.11). Hydra tries various combinations of usernames and passwords (present in Usernames.txt and Passwords.txt) on the FTP server and outputs cracked usernames and passwords; this might take some time. On completion, cracked credentials appear. Try to log in to the FTP server using one of the cracked combinations; in this lab use Martin's credentials (Martin / apple). Type ftp [IP Address of Windows 11] and press Enter; enter Martin's user credentials to check successful login. An ftp terminal appears. Type mkdir Hacked and press Enter to remotely create a directory named Hacked on the Windows 11 machine through the ftp terminal. Click Windows 11 to switch to the Windows 11 machine and navigate to C:\FTP; view the directory named Hacked. You have successfully gained remote access to the FTP server by obtaining appropriate credentials. Click Parrot Security to switch back. Enter help to view all other commands available through the FTP terminal. On completing the task, enter quit to exit the ftp terminal. Close all open windows on both Parrot Security and Windows 11 machines.

Notes: Versions/website appearance may differ; process same. Use cracked credentials only in authorized lab environments. Hydra syntax: -L usernames file, -P passwords file, target ftp://IP.
