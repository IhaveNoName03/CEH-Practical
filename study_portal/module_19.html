Cloud Computing

Cloud computing is an emerging technology that delivers computing services such as online business applications, online data storage, and webmail over the Internet. Cloud implementation enables a distributed workforce, reduces organization expenses, provides data security, etc. As enterprises are increasingly adopting cloud services, cloud systems have emerged as targets for attackers to gain unauthorized access to the valuable data stored in them. Therefore, it is essential to regularly perform pen testing on cloud systems to monitor their security posture.

Security administrators claim that cloud systems are more vulnerable to DoS assaults, because they involve numerous individuals or clients, making DoS assaults potentially very harmful. Because of the high workload on a flooded service, these systems attempt to provide additional computational power (more virtual machines, more service instances) to cope with the workload, and they will eventually fail. Although cloud systems try to thwart attackers by providing additional computational power, they inadvertently aid attackers by allowing the most significant possible damage to the availability of a service - a process that starts from a single flooding-attack entry point. Thus, attackers need not flood all servers that provide a particular service but merely flood a single, cloud-based address to a service that is unavailable. Thus, adequate security is vital in this context, because cloud-computing services are based on sharing.

Scenario: As an ethical hacker and penetration tester, you must have sound knowledge of hacking cloud platforms using various tools and techniques. The labs in this module will provide you with real-time experience in exploiting the underlying vulnerabilities in a target cloud platform using various hacking methods and tools. However, hacking the cloud platform may be illegal depending on the organization's policies and any laws that are in effect. As an ethical or pen tester, you should always acquire proper authorization before performing system hacking.

Objective: The objective of the lab is to perform cloud platform hacking and other tasks that include, but are not limited to: Performing S3 bucket enumeration; Exploiting misconfigured S3 buckets; Escalating privileges of a target IAM user account by exploiting misconfigurations in a user policy.

Cloud services are classified into three categories, namely infrastructure-as-a-service (IaaS), platform-as-a-service (PaaS), and software-as-a-service (SaaS), which offer different techniques for developing cloud.

Overview of Cloud Computing & Enumeration

Cloud computing refers to on-demand delivery of IT capabilities, in which IT infrastructure and applications are provided to subscribers as metered services over a network. Cloud services are classified into three categories: infrastructure-as-a-service (IaaS), platform-as-a-service (PaaS), and software-as-a-service (SaaS). Enumeration tools collect detailed information about target systems to exploit them; information collected by S3 enumeration tools consists of a list of misconfigured S3 buckets available publicly, which attackers can exploit to gain unauthorized access, modify, delete, and exfiltrate bucket content. S3 buckets store text documents, PDFs, videos, images, etc., and require a unique bucket name. Techniques to identify AWS S3 buckets include: inspecting HTML source for bucket URLs; brute-forcing URLs with Burp Suite; finding subdomains with Findsubdomains/Robtex; reverse IP search with Bing; advanced Google hacking with "inurl".

Key Concepts
  • Cloud computing: On-demand delivery of IT capabilities as metered services over a network.
  • IaaS (Infrastructure as a Service): Provider supplies virtualized compute, storage, and network; customer manages OS, middleware, apps, and data.
  • PaaS (Platform as a Service): Provider manages platform/runtime/OS; customer manages applications and data.
  • SaaS (Software as a Service): Provider delivers complete software application; customer simply uses it.
  • Deployment models: Public, private, hybrid, and community clouds.
  • AWS (Amazon Web Services): Cloud platform providing IaaS/PaaS/SaaS; organized into regions and availability zones (AZs).
  • Region / AZ: Geographic locations; AZs are isolated data centers within a region.
  • S3 (Simple Storage Service): Object storage; buckets (containers), objects (files), keys (names), metadata.
  • Bucket naming: Globally unique, DNS-style names.
  • S3 access controls: ACLs, bucket policies, IAM policies, presigned URLs.
  • Public/open buckets: Misconfigured to allow anonymous read/write, enabling data theft and file injection.
  • Enumeration: Brute-forcing bucket names/permutations to find publicly accessible buckets.
  • lazys3: Ruby script that brute-forces AWS S3 buckets using permutations; obtains publicly accessible buckets; can search buckets of a specific company by name.
  • S3Scanner: Finds open S3 buckets and dumps their contents; takes a list of bucket names; outputs found buckets; dumps/lists contents locally.
  • Other enumeration tools: S3Inspector, s3-buckets-bruteforcer, Mass3, Bucket Finder, s3recon, cloud_enum.
  • AWS CLI: Unified command-line tool to manage AWS services; configured with Access Key ID, Secret Access Key, default region, output format.
  • S3 CLI commands: aws s3 ls, aws s3 mv, aws s3 rm, aws s3api list-buckets.
  • Exploiting open buckets: Add/move/delete files, inject malware into bucket files, exfiltrate data.
  • IAM (Identity and Access Management): Manages users, groups, roles, and policies.
  • Policy: JSON document defining permissions (Effect, Action, Resource).
  • Privilege escalation: Horizontal (same-level access) and vertical (higher privileges).
  • Misconfigured user policy: Permissions such as iam:CreatePolicy, iam:AttachUserPolicy, iam:ListUserPolicies, sts:AssumeRole, iam:ListRoles can be exploited to attach an admin policy.
  • AdministratorAccess policy: Action "*" Resource "*" grants full administrator access.
  • Shared responsibility model: Provider secures cloud infrastructure; customer secures data, IAM, configuration, and network.
  • Cloud security threats: DoS, data breaches, misconfigurations, AAA vulnerabilities, hypervisor vulnerabilities, unclear roles.
  • Metadata service (IMDS): 169.254.169.254 provides instance metadata/credentials; a common SSRF target.

Defenses
  • Apply least privilege in IAM: grant only required permissions; avoid wildcard Action/Resource.
  • Block public access at account and bucket level; review bucket ACLs and policies.
  • Enable S3 Block Public Access and use private buckets by default.
  • Encrypt data at rest (SSE-S3/SSE-KMS) and in transit (TLS).
  • Enable MFA, strong passwords, and rotate access keys regularly.
  • Enable CloudTrail, S3 access logging, and GuardDuty for monitoring.
  • Use IAM roles instead of long-lived access keys; enforce SCPs in Organizations.
  • Restrict iam:CreatePolicy/AttachUserPolicy and sts:AssumeRole to trusted principals.
  • Validate IAM policies; avoid misconfigured user policies allowing privilege escalation.
  • Disable unused regions and services; use VPC endpoints and network segmentation.
  • Protect IMDS: enforce IMDSv2 and restrict SSRF vectors.
  • Educate users on social engineering risks for credential theft.
