Hacking Web Applications

A web application is a software application running on a web browser that allows a web user to submit data to and retrieve it from a database over the Internet or within an intranet. Web applications have helped to make web pages dynamic as they allow users to communicate with servers using server-side scripts. They allow users to perform specific tasks such as searching, sending emails, connecting with friends, online shopping, and tracking and tracing.

Scenario: Entities develop various web applications to offer their services to users via the Internet. Whenever users need access to such services, they can request them by submitting the uniform resource identifier (URI) or uniform resource locator (URL) of the web application in a browser. Common web applications include webmail, online retail sales, online auctions, wikis, and many others. With the wide adoption of web applications as a cost-effective channel for communication and information exchange, they have also become a major attack vector for gaining access to organizations' information systems. Web applications are an integral component of online business. Everyone connected via the Internet uses an endless variety of web applications for different purposes, including online shopping, email, chats, and social networking. Increasingly, web applications are becoming vulnerable to more sophisticated threats and attack vectors.

Objective: Perform web application hacking and other tasks that include, but are not limited to: footprinting a web application using various information-gathering tools; performing web spidering, detecting load balancers, and identifying web server directories; performing web application vulnerability scanning; performing brute-force and CSRF attacks; exploiting parameter tampering and XSS vulnerabilities; exploiting WordPress plugin vulnerabilities; exploiting remote command execution vulnerability; exploiting file upload vulnerability; gaining backdoor access via a web shell; detecting web application vulnerabilities using various web application security tools.

Overview of Web Applications: Web applications provide an interface between end-users and web servers through a set of web pages generated at the server end or that contain script code to be executed dynamically in a client's Web browser. Web applications run on web browsers and use a group of server-side scripts (such as ASP and PHP) and client-side scripts (such as HTML and JavaScript) to execute the application. The working of a web application depends on its architecture, which includes the hardware and software that performs tasks such as reading the request, searching, gathering, and displaying the required data. Web application hacking is the exploitation of applications via HTTP by manipulating the application logics via an application's graphical web interface, tampering with the URI or HTTP elements not contained in the URI. Methods include SQL injection, XSS, CSRF, and insecure communications.

Exam Essentials: Hacking Web Applications

Scenario & Objective

Scenario: An ethical hacker or penetration tester must test web applications for various attacks such as brute-force, XSS, parameter tampering, and CSRF, and then secure the web applications from such attacks. Web applications are an integral component of online business and have become a major attack vector for gaining access to organizations' information systems. Even a single vulnerability may allow an attacker to compromise the application or the entire network.

Objective: Footprint a web application using various information-gathering tools; perform web spidering, detect load balancers, and identify web server directories; perform web application vulnerability scanning; perform brute-force and CSRF attacks; exploit parameter tampering and XSS vulnerabilities; exploit WordPress plugin vulnerabilities; exploit remote command execution; exploit file upload vulnerabilities; gain backdoor access via a web shell; detect web application vulnerabilities using various web application security tools.

Overview of Web Application Footprinting

Web infrastructure footprinting helps identify vulnerable web applications, understand how they connect with peers and the technologies they use, and find vulnerabilities in specific parts of the web app architecture. Footprinting tasks: Server Discovery (Whois, DNS interrogation, port scanning), Service Discovery (services running on web servers as attack paths), Server Identification (banner grabbing for make/version), Hidden Content Discovery (content/functionality not directly linked). Attackers use web spidering/crawling to discover hidden content, backup copies, config/log files, and new functionality.

Key Concepts
  • Web Application: Software running in a browser that lets users submit/retrieve data from a database over the Internet or intranet; uses server-side scripts (ASP, PHP) and client-side scripts (HTML, JavaScript); dynamic pages generated at server or executed in browser.
  • Web Application Hacking: Exploitation via HTTP by manipulating application logics through the graphical web interface, tampering with URI or HTTP elements not in the URI. Methods: SQL injection, XSS, CSRF, insecure communications.
  • Web Spidering / Crawling: Recursively discovering links and hidden content of a target site (OWASP ZAP). Reveals hidden functionality, backup copies, config/log files, backup archives, and unlinked new functionality.
  • Load Balancers: DNS (Layer 4) and HTTP (Layer 7) load balancers distribute web server load. Detected via dig (multiple IPs resolving to one host) and lbd (DNS/HTTP load balancers via Server/Date headers).
  • Directory Enumeration: Identifying exposed files/directories via Nmap http-enum, Gobuster, Dirsearch (extensions, status-code exclusions).
  • Vulnerability Scanning: Vega discovers SQLi, XSS, sensitive info disclosure, etc. Other tools: WPScan, Arachni, AppSpider, Uniscan.
  • Clickjacking (UI Redress): Using transparent/opaque layers to trick users into clicking hidden elements; tested with ClickjackPoc.
  • Brute-Force (Burp Intruder): Cluster bomb attack iterating username/password combinations against login forms; success indicated by differing Status/Length (e.g., 302 / 1134).
  • Parameter Tampering: Manipulating client-server parameters (IDs, prices, permissions) to access other users' data or escalate privileges.
  • XSS (Cross-Site Scripting): Injecting client-side scripts into dynamic pages viewed by other users (stored/reflected). Identified with PwnXSS; exploited by injecting payloads in input fields.
  • CSRF (Cross-Site Request Forgery): Forcing an authenticated user's browser to send unintended requests to a vulnerable site; exploited via malicious HTML (e.g., leenk.me plugin CSRF).
  • WordPress Enumeration (WPScan): Enumerate plugins (--enumerate vp) and users (--enumerate u) with API token; exploit vulnerable plugins (akismet, leenkme).
  • Metasploit wordpress_login_enum: Dictionary attack against WordPress logins using PASS_FILE, RHOSTS, RPORT, TARGETURI, USERNAME.
  • Remote Command Execution (DVWA): Command injection via DVWA at Low security; chain commands with | (hostname, whoami, tasklist, net user, etc.); create admin account and RDP in.
  • File Upload (DVWA): Upload PHP meterpreter payload at Low security; bypass Medium (Burp rename to .php) and High (GIF header + copy to .php via command injection); establish Meterpreter session.
  • Log4j (CVE-2021-44228): Zero-day RCE via JNDI/LDAP lookup in Log4j; payload in input field yields reverse shell as root.

Defenses
  • Input validation and output encoding to prevent XSS and parameter tampering.
  • CSRF tokens in forms and SameSite cookies to block CSRF.
  • Secure file upload: validate extension, MIME type, content; store outside web root; rename files.
  • Disable dangerous functions and command injection entry points; use allow-lists for input.
  • Web Application Firewall (WAF) and IDS/IPS; patch Log4j and disable JNDI lookups.
  • Strong passwords, account lockout, and MFA to resist brute-force.
  • Keep WordPress/plugins updated; remove unused plugins; use security plugins.
  • Restrict HTTP methods, hide server banners, configure security headers (X-Frame-Options against clickjacking).
