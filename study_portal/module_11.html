Session Hijacking

A session hijacking attack refers to the exploitation of a session token-generation mechanism or token security controls that enables an attacker to establish an unauthorized connection with a target server. The attacker guesses or steals a valid session ID (which identifies authenticated users) and uses it to establish a session with the server.

Scenario: As an ethical hacker or penetration tester, you should understand different session hijacking concepts, how attackers perform application- and network-level session hijacking, and the various tools used to launch this kind of attack. You should also be able to implement security measures at both the application and network levels to protect your network from session hijacking. Application-level hijacking involves gaining control over the Hypertext Transfer Protocol (HTTP) user session by obtaining the session IDs. Network-level hijacking is prevented by packet encryption, which can be achieved with protocols such as IPsec, SSL, and SSH.

Exam Essentials: Session Hijacking

Exam Essentials

Scenario

As an ethical hacker or penetration tester, you should understand different session hijacking concepts, how attackers perform application- and network-level session hijacking, and the various tools used to launch this kind of attack. You should also be able to implement security measures at both the application and network levels to protect your network from session hijacking. Application-level hijacking involves gaining control over the Hypertext Transfer Protocol (HTTP) user session by obtaining the session IDs. Network-level hijacking is prevented by packet encryption, which can be achieved with protocols such as IPsec, SSL, and SSH.

Objective

Hijack a session by intercepting traffic between server and client; steal a user session ID by intercepting traffic; detect session hijacking attacks.

Overview of Session Hijacking

Session hijacking can be either active or passive, depending on the degree of involvement of the attacker:

  • Active session hijacking: An attacker finds an active session and takes it over.
  • Passive session hijacking: An attacker hijacks a session, and, instead of taking over, monitors and records all the traffic in that session.

Session hijacking can be divided into three broad phases:

  • Tracking the Connection: The attacker uses a network sniffer to track a victim and host, or uses a tool such as Nmap to scan the network for a target with a TCP sequence that is easy to predict.
  • Desynchronizing the Connection: A desynchronized state occurs when a connection between the target and host has been established, or is stable with no data transmission, or when the server's sequence number is not equal to the client's acknowledgment number (or vice versa).
  • Injecting the Attacker's Packet: Once the attacker has interrupted the connection between the server and target, they can either inject data into the network or actively participate as the man-in-the-middle, passing data between the target and server, while reading and injecting data at will.

Session hijacking operates at two levels. Network-level hijacking targets the TCP/IP session (packet sniffing/spoofing, TCP sequence prediction) and is mitigated by packet encryption (IPsec, SSL/TLS, SSH). Application-level hijacking targets the HTTP user session by obtaining session IDs (cookies, URL parameters, hidden form fields) and includes XSS, CSRF, session fixation, session prediction, and sidejacking.

Key Concepts

  • Session: A semi-permanent interactive connection between two communicating devices (client and server) over a network, maintained via a session ID/token.
  • Session ID: A unique token assigned to a user after authentication; identifies authenticated users. Attackers steal or guess it to hijack the session. Carried in cookies, URL parameters, or hidden form fields.
  • Active Session Hijacking: Attacker finds an active session and takes it over (impersonates the user). Involves desynchronizing and injecting packets.
  • Passive Session Hijacking: Attacker monitors and records all traffic in the session without taking over (sniffing).
  • Network-Level Session Hijacking: Hijacks the TCP connection between client and server (TCP/IP session hijacking, MITM). Prevented by packet encryption (IPsec, SSL/TLS, SSH).
  • Application-Level Session Hijacking: Gains control of the HTTP user session by obtaining session IDs. Techniques: XSS, CSRF, session fixation, session prediction, sidejacking.
  • TCP Hijacking: Exploits TCP sequence numbers to insert packets into an established connection. Phases: tracking the connection, desynchronizing, injecting. Can lead to MITM and DoS. Relies on predictable ISNs; modern OSs use random ISNs.
  • Man-in-the-Middle (MITM): Attacker places themselves between client and server, intercepting and possibly modifying traffic in both directions; captures credentials/session tokens.
  • Denial of Service (DoS): Flooding the target with requests after sniffing sensitive info, exhausting resources.
  • XSS (Cross-Site Scripting): Injection of malicious scripts into trusted web pages; used to steal session cookies/tokens. Types: stored (persistent), reflected (non-persistent), DOM-based. Mitigation: input validation, output encoding, HttpOnly cookies.
  • CSRF (Cross-Site Request Forgery): Tricks an authenticated user's browser into sending an unwanted request to a trusted site; the session cookie is sent automatically. Mitigation: CSRF tokens, SameSite cookies, re-authentication for sensitive actions.
  • Session Fixation: Attacker forces a known session ID on the victim; after the victim authenticates, the attacker reuses that ID. Mitigation: regenerate session ID on login/authentication, invalidate old IDs.
  • Session Prediction: Guessing/brute-forcing predictable session IDs. Mitigation: cryptographically strong random session tokens, sufficient entropy.
  • Sidejacking: Stealing a session cookie transmitted over unencrypted HTTP (e.g., on open Wi-Fi) using a packet sniffer (Firesheep). Mitigation: HTTPS for all authenticated traffic, secure cookies.
  • Session Sniffing: Capturing session tokens sent in cleartext over HTTP/FTP/Telnet etc.
  • Session Token Locations: Cookies (most common), URL query parameters, hidden form fields, HTTP headers.

Tools

Zed Attack Proxy (ZAP) bettercap Hetty Wireshark Firesheep Ettercap Burp Suite

  • ZAP: Intercepting proxy and web app scanner; traps requests/responses with breakpoints; rewrites traffic; used to hijack sessions and view AJAX calls.
  • bettercap: MITM framework; ARP spoofing, HTTP/HTTPS proxy, SSL stripping, credential sniffing; modules: net.probe, net.recon, arp.spoof, http.proxy, net.sniff.
  • Hetty: HTTP toolkit for security research; MITM, request editing/replay, proxy logs; alternative to Burp Suite Pro.
  • Wireshark: Packet capture/analysis; detects session hijacking via ARP floods and credential extraction (filters like http.request.method == POST).

Defenses

  • HTTPS everywhere: Encrypt all traffic containing session tokens; prevents sniffing/sidejacking.
  • Secure cookies: Set Secure, HttpOnly, and SameSite attributes on session cookies.
  • HSTS (HTTP Strict Transport Security): Forces browsers to use HTTPS, prevents SSL stripping/downgrade.
  • Network encryption: IPsec, SSL/TLS, SSH for network-level protection.
  • Regenerate session ID: On login and privilege change; prevents session fixation.
  • Strong session tokens: High entropy, unpredictable; prevents session prediction.
  • Short timeouts & logout: Idle/absolute session expiration; invalidate on logout.
  • Avoid URL session IDs: Don't pass session IDs in URLs/query strings; use cookies.
  • Input validation / output encoding: Mitigate XSS that steals cookies.
  • CSRF tokens: Anti-CSRF tokens and SameSite cookies.
  • IDS/IPS & monitoring: Detect ARP floods and anomalous sessions; manual Wireshark analysis.

Exam Tips

  • Active = take over the session; passive = monitor/record only.
  • Network-level hijacking = TCP/IP session (encryption prevents it); application-level = HTTP session via session IDs.
  • TCP hijacking phases: tracking -> desynchronizing -> injecting.
  • XSS steals session cookies; CSRF forces authenticated actions; fixation reuses a known ID; prediction guesses IDs; sidejacking sniffs cookies over HTTP.
  • Session fixation fix = regenerate session ID on authentication.
  • Sidejacking defense = HTTPS + secure cookies; Firesheep is the classic tool.
  • HSTS prevents SSL stripping (bettercap sslstrip).
  • Secure + HttpOnly + SameSite cookies are the key cookie defenses.
  • High volume of ARP requests in Wireshark indicates ARP spoofing/bettercap.
  • Always obtain proper authorization before performing session hijacking tests.

Lab 1: Perform Session Hijacking - Task 1: Hijack a Session using Zed Attack Proxy (ZAP)

Zed Attack Proxy (ZAP 2.11.1) / Google Chrome

What/when: Zed Attack Proxy (ZAP) is an integrated penetration testing tool for finding vulnerabilities in web applications. It offers automated scanners as well as tools that allow you to find security vulnerabilities manually, and is designed for people with a wide range of security experience. ZAP lets you see all requests you make to a web app and all responses you receive, including AJAX calls that may not otherwise be visible. You can also set breakpoints to change requests and responses in real time. Here we hijack a session using ZAP as an intercepting proxy: the victim's browser (Windows 11) is pointed at the attacker's ZAP instance (Windows Server 2019, 10.10.1.19:8080), ZAP traps every request/response with a global breakpoint, and the attacker rewrites the victim's navigation from www.moviescope.com to www.goodshopping.com so the victim sees attacker-chosen content while the address bar still shows the original site. Lab 1: Perform Session Hijacking - Task 2: Intercept HTTP Traffic using bettercap

bettercap / Mozilla Firefox

What/when: In an MITM attack the attacker places himself between the authorized client and the web server so all information traveling in either direction passes through them. bettercap is a powerful, flexible, portable tool for performing various MITM attacks against a network, manipulating HTTP, HTTPS, and TCP traffic in real time, sniffing credentials, etc. Here bettercap on Parrot Security (eth0) performs ARP spoofing against Windows 11 (10.10.1.11), enables an HTTP proxy with SSL stripping, and sniffs for payloads matching the regex '.*password=.+', capturing the victim's browsing and plaintext credentials (sam/test) on the http-based www.moviescope.com. bettercap collects all HTTP logins used by routers, servers, and websites without SSL; to sniff HTTPS traffic enable SSL strip via set http.proxy.sslstrip true.

cd
