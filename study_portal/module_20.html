Cryptography

Cryptography is the practice of concealing information by converting plain text (readable format) into cipher text (unreadable format) using a key or encryption scheme: it is the process of converting data into a scrambled code that is sent across a private or public network. "Cryptography" comes from the Greek words kryptos ("concealed, hidden, veiled, secret, or mysterious") and graphia ("writing"); thus cryptography is "the art of secret writing."

There are two types of cryptography, determined by the number of keys employed for encryption and decryption: Symmetric Encryption (secret-key, shared-key, private-key) uses the same key for encryption and decryption; Asymmetric Encryption (public-key) uses different keys (public and private) for encryption and decryption.

Scenario: With the increasing adoption of the Internet for business and personal communication, securing sensitive information such as credit-card and personal identification numbers (PINs), bank account numbers, and private messages is becoming increasingly important, and yet more difficult to achieve. Today's information-based organizations extensively use the Internet for e-commerce, market research, customer support, and a variety of other activities, so data security is critical to online businesses and privacy of communication. As an ethical hacker or penetration tester, you should suggest to your client proper encryption techniques to protect data, both in storage and during transmission. The labs in this module demonstrate the use of encryption to protect information systems in organizations.

Overview of Cryptography: Cryptography and cryptographic ("crypto") systems help in securing data from interception and compromise during online transmissions. Cryptography enables securing transactions, communications, and other processes performed in the electronic world, and is additionally used to protect confidential data such as email messages, chat sessions, web transactions, personal data, corporate data, e-commerce applications, etc.

Exam Essentials: Cryptography

Scenario & Objective

Scenario: With the increasing adoption of the Internet for business and personal communication, securing sensitive information such as credit-card and PINs, bank account numbers, and private messages is becoming increasingly important, and yet more difficult to achieve. Data security is critical to online businesses and privacy of communication. As an ethical hacker/pen tester, suggest proper encryption techniques to protect data in storage and during transmission; the labs demonstrate the use of encryption to protect information systems in organizations.

Objective: Use encryption to conceal data: generate hashes and checksums; calculate encrypted value of selected files; encrypt/decrypt; perform file and data encryption; create self-signed certificates; perform email encryption; perform disk encryption; perform cryptanalysis.

Overview of Cryptography

"Cryptography" = Greek kryptos (concealed/secret) + graphia (writing) = "art of secret writing." Cryptography conceals information by converting plain text into cipher text using a key or encryption scheme; data becomes a scrambled code transmitted over private/public networks. Cryptographic tools convert plain text into cipher text using keys. Hash functions distill any block of information into a single fixed-length message digest (128-256 bits); if any input bit changes, every output bit has a 50% chance of changing; finding another file with the same digest is computationally infeasible.

Types by number of keys: Symmetric Encryption (secret-key / shared-key / private-key) uses the same key for encryption and decryption. Asymmetric Encryption (public-key) uses different keys: a public key and a private key.

Key Concepts
  • Plain text / Cipher text: Readable input vs. scrambled, unreadable output of encryption.
  • Symmetric encryption: Same key for encrypt and decrypt (AES, DES, 3DES, RC2, RC4, Blowfish, Twofish). Fast; key distribution problem.
  • Asymmetric (public-key) encryption: Key pair - public key (shared) encrypts/verifies, private key (secret) decrypts/signs (RSA, ECC, Diffie-Hellman, ElGamal).
  • Hashing / Message digest: One-way function producing fixed-length digest (MD2, MD4, MD5, SHA-1, SHA-256/384/512, RIPEMD160). Used for integrity, passwords, digital signatures. Avalanche effect: tiny input change drastically changes output.
  • HMAC: Hash-based Message Authentication Code - hash + secret key for integrity and authenticity.
  • Checksums: CRC32, Adler32 - error detection, not cryptographically strong.
  • Block vs. stream ciphers: Block ciphers operate on fixed-size blocks (ECB, CBC, CFB, OFB, CTR modes); stream ciphers encrypt bit/byte at a time (RC4).
  • PKI (Public Key Infrastructure): Framework of CAs, certificates, and registration authorities that issue/manage/revoke public-key certificates.
  • Digital certificate / X.509: Binds a public key to an identity (person, server, org); contains subject, issuer, validity, public key, signature.
  • CA (Certificate Authority): Trusted entity that signs certificates; self-signed certificates are signed by the same entity whose identity they verify.
  • SSL/TLS: SSL uses RSA asymmetric (public key) encryption to encrypt data transferred over SSL connections; TLS uses a symmetric key for bulk encryption, an asymmetric key for authentication and key exchange, and MACs for message integrity. HTTPS = HTTP over TLS on TCP 443.
  • Digital signature: Uses asymmetric cryptography to simulate a signature in digital form; provides authenticity, integrity, non-repudiation.
  • Email encryption: Hides email content from eavesdroppers by encrypting into unreadable form using public/private keys (PGP, GPG, S/MIME, RMail).
  • PGP / GPG: Pretty Good Privacy encrypts/decrypts data providing authentication and cryptographic privacy; GPG is the free implementation of the OpenPGP standard.
  • Disk encryption: Protects confidentiality of data on disk by converting it into unreadable code (VeraCrypt, BitLocker, Rohos); works even when OS is inactive; on-the-fly encryption.
  • VeraCrypt: On-the-fly-encrypted volumes; entire filesystem encrypted (names, free space, metadata); hidden volumes; needs password/keyfile.
  • BitLocker: Full-disk encryption using TPM (Trusted Platform Module) microchip; encrypts entire Windows volumes; recovery key backup.
  • Cryptanalysis: Breaking ciphers - linear, differential, integral cryptanalysis; classical techniques (Caesar, Vigenere, Playfair, transposition, substitution, frequency analysis).
  • Steganography: Hiding secret data within another file (image, audio, video, text) so the existence of the message is concealed (vs. cryptography which scrambles content).
  • Encoding vs. encryption: Encoding (Base64, hex) is reversible without a key and is not security; encryption requires a key.

Defenses
  • Use strong, modern algorithms (AES-256, RSA-2048+, ECC, SHA-256+); avoid DES, 3DES, RC4, MD5, SHA-1 for security.
  • Protect private keys and passwords; use key management (HSM, KMS), never hardcode keys.
  • Enforce TLS 1.2/1.3 with strong cipher suites; disable SSLv2/3, TLS 1.0/1.1; use HSTS.
  • Use certificates from trusted CAs; validate chains; monitor expiry; avoid self-signed in production.
  • Encrypt data at rest with full-disk/volume encryption (BitLocker, VeraCrypt) and protect recovery keys.
  • Encrypt sensitive email with S/MIME or PGP/GPG; verify signatures.
  • Use salted, slow password hashing (bcrypt, scrypt, Argon2) for stored passwords; never plain MD5.
  • Apply integrity checks (HMAC, signed hashes) and verify file hashes after transfer.
  • Rotate keys; revoke compromised certificates; use forward secrecy (ECDHE).
  • Hide metadata where possible; avoid leaking info via file names/timestamps.
  • Monitor for cryptanalysis attempts, weak cipher usage, and certificate anomalies.
Exam Tips
  • Symmetric = same key (fast, bulk data); asymmetric = key pair (key exchange, signatures); hybrid systems use asymmetric to exchange a symmetric session key.
  • MD5 = 128-bit digest; SHA-1 = 160-bit; SHA-256 = 256-bit; SHA-512 = 512-bit.
  • MD5/SHA-1 are broken for collision resistance; use SHA-256+ for integrity.
  • RSA is asymmetric; AES is symmetric; DES/3DES symmetric block; RC4 stream.
  • Digital signature = hash encrypted with sender's private key; verified with sender's public key.
  • Certificate binds public key to identity; CA signs it; self-signed = issuer == subject.
  • SSL/TLS: asymmetric for handshake/key exchange, symmetric for bulk data, MAC for integrity.
  • BitLocker uses TPM for boot integrity; recovery key saved to file; Compatible mode for movable drives.
  • VeraCrypt: create encrypted file container; mount as virtual drive; dismount hides data; password qwerty@123 in lab.
  • RMail: Encrypt option with Transmission-auto-decrypts for receiver; E-Sign with Web Sign.
  • CrypTool: RC2 (key 05 hex) and Triple DES ECB (key 12 hex) encrypt/decrypt.
  • AlphaPeeler: DES-EDE (CBC) with passphrase test@123.
  • HashCalc supports MD2, MD4, MD5, SHA1, SHA2 (256/384/512), RIPEMD160, PANAMA, TIGER, CRC32, ADLER32, eDonkey/eMule.
  • Steganography hides existence of data; cryptography hides content.
  • Exam often asks which tool/algorithm is symmetric vs. asymmetric, hash length, and port numbers.
